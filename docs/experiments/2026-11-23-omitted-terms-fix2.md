# omitted語を常に表記で書く追加学習（FIX2）

## 目的

[FIX1](2026-11-23-omitted-terms-fix.md)は、学習時の一覧かsegment-merge後の文に表記がある場合にだけ、omitted語を正解文で表記に置き換えた。上限32の一覧ではtest-novelがRSI-0.8Bの379/500からFIX-0.8B-contの407/500に増えた。一方、PMの別測定では、本人の録音50件でCERが3.86%から5.15%、用語正答数が61/67から59/67に悪化した。

FIX2では、一覧とASR入力の作り方を保ち、omitted語は手掛かりの有無にかかわらず正解文に表記を書く。合成音声のvalで一覧外の学習済み語がFIX-0.8B-contより増えるか、test-novelでの改善が維持されるか、発話に無い用語の挿入が増えるかを確かめる。片方の指標だけの改善では、両立を確認したとは判断しない。

## 学習データ

facultyの `~/voiceime-work-wops/fix1/data/` にある元データと拡張データから、`~/voiceime-work-wops/fix2/data/` に作成した。規則2の既存の正解文を使い、規則3の読みは表記に置き換え、規則4の書き換え候補は無条件で使う。新たに表記を書く語を `terms` に加え、規則3の一覧除外と規則4の動的な正解選択を外した。元行の `glossary` はASR合成と無作為に混ぜる語の選択にも使うため、書き換えた語をここには追加していない。

fix1が除外した元3行と拡張2行は引き継いだ。omitted以外の行はバイト単位で一致し、全行の順序と入力を照合した。データ作成では既存のheld-out除外表とも照合した。test-novelは評価工程で使った。変換元と変換後のSHA-256は[変換監査](../../runs/weightops/fix2/fix-audit.json)に記録した。

| データ | 全行 | omitted行 | 保存した正解文を変更 | 一覧外で表記を正解にした行 | 一覧とsegment-merge後の両方に表記なし |
| --- | ---: | ---: | ---: | ---: | ---: |
| 元 | 95,931 | 8,369 | 7,274 | 352/8,369（4.21%） | 328 |
| 拡張 | 36,778 | 1,822 | 225 | 245/1,822（13.45%） | 225 |
| 合計 | 132,709 | 10,191 | 7,499 | 597/10,191（5.86%） | 553 |

全132,709行を学習時と同じDatasetから1回ずつ取り出し、トークン化直前の一覧と正解文を照合した。omitted行で表記が正解文に無い例は0件だった。監査では2,000行ごとにseedを固定した。同じ取り出しにFIX1の動的な規則を当てると、正解文が実際に変わるのは553行だった。 [全行監査](../../runs/weightops/fix2/verify-dynamic.json)

## 学習条件

| 条件 | 初期値 | キュージョブ |
| --- | --- | --- |
| FIX2-0.8B-cont | `outputs/RSI-0.8B/best` | `60-wops-fix2-08b-cont.sh` |
| FIX2-0.8B-contfix | `outputs/FIX-0.8B-cont/best` | `60-wops-fix2-08b-contfix.sh` |

初期値のパスはfacultyの `~/voiceime-work-wops/` からの相対パス。FIX-0.8B-contと同じく全層を1 epoch、学習率1e-5、batch 16 × accumulation 2、seed 0、最大1,024トークン、学習時の一覧は上限20、混ぜ物は最大8語、用語drop 0で学習する。cuDNN SDPAを無効にしてgradient checkpointingを使う。970件のval-selectで250 stepごとに損失を測り、最良の `best` と最後の `final` を `fix2/outputs/<条件>/` に保存する。

動的な切り替えを追加する前の `rsi1/train_rsi.py` と `rsi1/train_support.py` を再利用した。FIX1の学習コードとの差を照合し、正解選択と一覧除外以外の差が引数の説明文だけであることを確認した。 [学習引数と実行手順](../../runs/weightops/fix2/train-and-eval.sh)

| 条件 | 開始–終了（JST、評価込み） | 最良のval loss | 最後のstep |
| --- | --- | ---: | ---: |
| FIX2-0.8B-cont | 22:34–23:53（GPU1） | 3,250 stepで0.1160 | 4,148 |
| FIX2-0.8B-contfix | 22:38–23:58（GPU3） | 4,148 stepで0.1296 | 4,148 |

両ジョブは終了コード0で完了し、保存した重みが各条件の `best` と `final` の2つであることを確認した。評価直後に割当GPUの計算プロセスが0件で、終了後のプロセス一覧にも両条件の学習プロセスはなかった。 [学習ログの集計](../../runs/weightops/fix2/training.json)

## 評価方法

facultyの `fix1/capacity-eval.sh <条件> <bestのパス>` で評価し、結果は `runs/capacity/<条件>/` に保存する。比較にはHaas 1回目とQwen 0.6Bで選んだ上限20・32・48の一覧を使った。valは合成音声1,000件の1,427用語、test-novelは合成音声500件の500用語。本人の録音はこの実験の対象外。

CER・正答数・取りこぼしの件数はFIX1と同じ採点コードで計算した。入力一覧を行単位で照合し、基準2本の保存済みスコアと一致した。2種類の取りこぼしは、同じ出現を両方に数えることがある。

- 一覧外の学習済み語は、共通の初期学習であるRSIの元データまたは拡張データの正解文に表記があり、`terms` にも記録された語（24,049種類）のうち、その評価行の一覧に無いval正解語を指す。出現数を分母とし、既存の正答数と同じ厳密表記で数える。
- 発話に無い用語の挿入は、行の入力一覧またはmanifestの用語集にある表記が出力に現れ、正解語にも発話原文・読みの文にも表記や読みがない場合の出現数。一覧からの挿入数も集計JSONに含める。

## 分かったこと

- FIX2の2条件は、一覧の全上限でFIX-0.8B-contより初見語を多く書けた。上限32では407/500からcontが412/500、contfixが411/500になった。contでは一覧に表記がある取りこぼしが35件から30件、segment-merge後に表記がある取りこぼしが6件から4件に減った。一方、発話に無い用語の挿入は39件から43件と42件に増えた。
- 一覧外の学習済み語は上限20で74/122から74/122と75/122、上限32で72/119から70/119と69/119、上限48で75/119から72/119と70/119だった。読み復元後も、この指標は同じだった。上限32では、contのval全体の用語正答数は1,357のまま、CERは2.76%から2.93%に増えた。contfixは用語正答数が1,349に下がり、CERは2.91%だった。
- 一覧外の学習済み語の回復と初見語の改善を両立する仮説は、この合成音声評価では支持されなかった。両条件ともseed 0の1回で、seed間のばらつきは未測定。本人の録音での影響は不明。

## 再実行

facultyで、スクリプトを `~/voiceime-work-wops/fix2/` に配置して実行する。以下は `fix2/data/` が存在しない状態での初回実行手順。

```bash
cd ~/voiceime-work-wops/fix2
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=../fix1 python3 prepare_fix2.py
bash train-and-eval.sh audit
```

学習と容量評価は、上記の2ジョブをfacultyのキューに登録する。採点は両ジョブの終了後にfacultyで行う。

```bash
source ~/voiceime-work-wops/rsi1/faculty-env.sh
export CUDA_VISIBLE_DEVICES=""
export PYTHONPATH="$PYTHONPATH:$WORK/fix1"
"$PY" "$WORK/fix2/score_fix2.py"
```
