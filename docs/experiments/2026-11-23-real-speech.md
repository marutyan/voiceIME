# 条件Dに投稿者字幕付き実音声を加える

## 仮説

合成音声だけの条件Dへ、実音声のASR仮説と忠実な字幕を加えると、実音声に特有のASR誤りがあっても本文を残しやすくなる。主判定は、PMがMacで測る本人50件のCER、削除数、用語正答数とする。実音声追加後に本人50件のCER・削除が改善しなければ仮説を支持しない。pub-evalは同じ300区間での相対比較に使う。

## 実行条件

| 条件 | 初期値 | 学習データ |
| --- | --- | --- |
| RSI-0.8B | `~/voiceime-work-wops/outputs/RSI-0.8B/best`（step 4,000） | 追加学習前の基準 |
| REAL-0.8B | RSI-0.8Bのbest | 条件Dの修正版95,931行、差し替えの修正版36,778行、実音声 |

19時の指示で初期値、教師文生成、比較基準をRSI-0.8Bのbestへ切り替えた。2種類の追加学習を予定していたところを、差し替えを含むREAL-0.8Bの1種類に変更した。

wopsの `fix1` を準備時点で確認し、学習前に完成した `fix2/data/train-fixed.jsonl` と `augmentation-fixed.jsonl` を採用した。修正版では元データ95,934行から3行、差し替え36,780行から2行を除外している。`fix2` は該当する `omitted_terms` の正解文を英字表記へ統一し、wopsの監査でカタカナのまま残った該当行が0件だった。学習前の差し替えデータと修正版のSHA-256は [frozen-inputs.json](../../runs/realspeech/frozen-inputs.json) に記録した。

- 実音声は `espnet/yodas3.1` 日本語、revision `3247e8cabda1e8e9418a6d8fe582e8c1abe75861`。`words` のある字幕行を一つも含まない動画を投稿者字幕扱いにする。pub-evalの93本を動画IDで除き、pub-pool動画は候補に含める。空行・効果音表記で区切り、字幕行間が1秒以内の連続行から、3〜15秒、空白を除く10〜80文字、日本語文字を含む区間を取る。上限40区間/動画、seed 0。字幕行を共有しない区間を優先し、30,000件に足りない分だけ同じ字幕行を使う別の時刻範囲を採る。
- facultyのCPUでtar headerを512 bytesずつRange取得し、選択したWebMだけを一時保存する。16kHz・モノラル・16bitのWAVへ区間を切り出し、フレーム数を字幕時刻に対して10ms以内で照合する。候補数・1区間の最大長・同時取得するWebMのサイズから、音声と一時ファイルを約30GB以下に抑える。
- ASRは `r3-multiasr-train-20261123` のQwen3-ASR 0.6B、日本語指定・空context・greedy・batch 32と、Haas ja v1.0 Q8_0、CUDA encoder・CPU decodeを再利用する。Haasヒントなし1回目とQwen仮説を改行で結合して用語を選び、Haasの2回目と `segment-merge` に使う。Haasは上限16語・240文字、整形用の一覧は上限20語。用語集は学習時の除外にtest-novel 500表記を加え、全角半角・大小の差も含めて除く。字幕とどちらかの初回ASR仮説の `voiceime.eval.metrics.calculate_cer` が15%以下なら残す。
- RSI-0.8Bのbestで整形した後、句読点・記号・空白を除いてcasefoldした文字列が字幕と一致すれば、その出力を正解とする。長さ上限で止まった出力を含む残りは、CERが低いASR仮説から、前後の文字が一致する位置および一致する末尾へ `、。！？` を写す。写せる箇所が無ければ字幕を保持する。用語集の英字表記に一致した字幕の語を記録する。字幕にないフィラー語形がASRにある件数は共通のフィラー定義で集計する。字幕本文・ASR本文に自然に現れたtest-novel表記は監査し、通常の500件比較に加えて、その表記を除いた共通分母でも用語正答を集計する。
- 追加学習は全層、1 epoch、学習率 `1e-5`、実効batch 32（16×2）、drop 0、seed 0、`--disable-cudnn-sdp`、gradient checkpointing。修正版の元データには条件DのASR・用語一覧と従来の加工を使う。損失はRSIと同じく、正解トークンを予測する位置だけを語彙へ射影して計算する。実音声には区間で得た仮説・一覧・教師文を固定して使い、用語差し替えには監査済みの仮説・一覧を使う。実音声が全学習行の20%を超える場合はseed 0で無作為抽出し、10%に満たなくても全件を使う。val loss最良と最後の重みを保存し、評価には最良を使う。
- val 1,000件とtest-novel 500件には既存条件Dの入力・固定一覧を使う。pub-eval 300件の入力は実音声学習候補と同じASR手順で生成し、CERによる除外を適用しない。RSIのvalとtest-novelは既存のTransformers BF16・greedy出力を再利用する。新規推論も同じ設定で実行し、同じ出力から `restore_listed_readings` あり・なしのCER、削除、用語正答を比較する。pub-evalでは字幕との相対差を扱い、フィラー評価の分母を置かない。

実験コードは [runs/realspeech](../../runs/realspeech/) に置いた。条件Dの実装基点は `eced52eb83b89e531dc9c7cb407a888fe93fe907`。ASRの再利用スクリプトのSHA-256は `7faf698cb45eb321735fe4f838aa7109675d8e917d4626b96d9be9b4c0756f0b`。差し替えデータのSHA-256 `9b2f8f37dcda4ad08a34c93110fd2647f3c00357a564588116483a5181156ded` は監査記録で確認した。CPU環境のPyArrowは26.0.1、httpx2は2.16.2、RapidFuzzは3.14.6。facultyで `bash ~/voiceime-work-real/scripts/run_pipeline.sh` が取得完了とジョブの終了を待ち、後続の処理を進める。

## 区間選定と取得

| 指標 | 件数・時間 |
| --- | ---: |
| メタデータ | 79,962動画、108 shard |
| 投稿者字幕のみ | 5,182動画 |
| pub-evalと重複するため除外 | 93動画 |
| 学習候補 | 30,000区間、1,465動画、49.38時間 |
| 学習候補のうち追加の連結区間 | 2,279区間 |
| 選定後のpub-eval動画との重複 | 0動画 |
| 検証済みWAV | 29,891区間、1,461動画、5.67 GB |
| WAVを取得できなかった区間 | 109区間 |

最初の32並列の取得はHugging FaceのHTTP 429で中断した。その後、12並列かつ全体で毎秒8リクエストを上限とし、429応答の解除時刻まで待機するよう変更した。既に形式・長さを検証できたWAVを再利用する。30,000区間の候補と取得済みWAVの件数は別に集計する。候補が多いtarシャード0105・0106は、それぞれ取得完了時点でASRキューへ送り、残るシャードの取得と並行できるようにした。[Hugging Face Hubのレート制限](https://huggingface.co/docs/hub/rate-limits)

0105のRange取得はHTTP 502が続き、15,088候補中7,228件で一度止まった。失敗した位置に同じRangeを再要求して206が返ることを確認し、一次取得が502で止まったシャードだけをその位置から再取得する処理を追加した。前回のWAVと認識結果を使い、再取得で増えた区間だけを補充ASRへ送る。

再取得した10シャードでWAVが8,079件増え、tarの読取エラーは全件解消した。残る109件は、WebMの取得が再試行後も失敗した40件、WAVの形式・長さの検証に通らなかった69件だった。学習用ASRに渡す4つの入力は合計29,891件。[extraction.json](../../runs/realspeech/extraction.json)

## 学習データ

学習候補29,891区間のASR後、15,015区間（50.23%）を採用した。CERが15%以下だったのは両ASRが8,587件、Haasのみが5,325件、Qwenのみが1,103件。除外は両方が15%超の14,856件と両方の出力が空の20件だった。正規化後に字幕が空だった区間は0件。[cer-filter.json](../../runs/realspeech/cer-filter.json)

教師文はRSIの出力3,093件、ASRから句読点を移した2,287件、元の字幕を保持した9,635件。英字の正解用語は427区間に519回、字幕にないフィラー語形がASRにある区間は964件だった。test-novelの表記が正解文に出た区間は0件で、ASR本文に2表記が各1件出た。[targets.json](../../runs/realspeech/targets.json)・[教師文の例30件](../../runs/realspeech/examples.jsonl)

学習に使う147,724行のうち実音声は15,015行（10.16%）で、採用した実音声をすべて使った。[REAL-0.8B.json](../../runs/realspeech/REAL-0.8B.json)

## 分かったこと

- pub-evalでは、読みの復元ありのCERが51.26%から44.86%に下がった。置換は620文字、挿入は299文字減った一方、削除は254文字増え、厳密用語正答は216件から201件に減った。字幕との相対比較では、CERの低下と内容保持・用語正答の改善は同時には起きなかった。
- test-novelでは読みの復元なしで359/500から384/500へ増えた。復元すると基準は388/500に達し、REALは384/500だった。実音声のASR本文に出た2表記を除いても、復元なしは358/498から383/498、復元ありは387/498から383/498で傾向は同じだった。
- valではCERが0.04ポイント上がり、厳密用語正答が7件減った。差には実音声に加え、用語の正解文修正と追加の1 epochも含まれる。学習seed間のばらつきは未測定。
- 本人50件でのCER・削除・用語正答は、PMがMacで測る。今回のpub-evalでは削除が増えたため、本人の録音で内容を残しやすくなるという仮説は未確認。
