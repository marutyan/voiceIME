# 条件Dの重み補間と用語誤りの分析（2026-11-23）

補間係数 α=0.25 は、0.8Bの親モデルで最良だったval用語1346/1427を維持し、test-novelを親の最良357/500から362/500に増やした。test-novelの最多は α=0.50 の364/500。補間3条件とも、val用語1356/1427とtest-novel 400/500の目標には届かなかった。0.8B-drop0と2B-drop0.075で正しい方の出力語を常に選べても、test-novelは374/500だった。

## 実験1　0.8Bの重み補間

### 仮説と評価条件

同じ初期値とデータで学習したD-0.8B-drop0とD-0.8B-drop0.075を補間すると、drop0.075のval用語とdrop0の初見語の強みを両立できる。各指標で親モデルの最良値以上になった条件があれば両立と判定する。目標はval用語95%以上、test-novel用語80%以上。

- 起点は `feat/formatter-r3` の `39bf927`。親はfacultyの `~/voiceime-work-fr3/outputs/formatter-sft3-d-{0.8b-drop0,0.8b-drop0075}-restart1/final`。両親の学習seedは0、2 epoch、実効batch 32、最終のbest checkpointはstep 5,996。
- CPUで `(1-α) × θ_drop0 + α × θ_drop0.075` をfloat32で計算し、親のBF16に戻して保存した。αは0.25、0.50、0.75。全320テンソルはBF16で、整数bufferはなかった。親のモデル設定とtokenizerはバイト単位で一致した。
- val 1,000行・1,427語、test-novel 500行・500語。既存Dと同じHaas 1回目、segment-merge、Qwen3-ASR 0.6B仮説、固定用語一覧を使用した。test-novelは既存の83語除外指定も引き継いだ。本人の録音やその評価出力は使用していない。
- NVIDIA H100、PyTorch `2.13.0+cu129`、Transformers `5.23.0`。既存launcherと同じBF16 greedy、batch 32、同じ出力整形とCER集計。用語は正解と同じ表記の出現を数える。評価器、レポート、入力監査の3ファイルは手元の起点の版とSHA-256で一致した。
- facultyの優先度70の3ジョブを実行した。実行内容は [launcher](../../runs/weightops/70-wops-soup.sh) と [補間コード](../../runs/weightops/interpolate.py)。最終重みはfacultyの `~/voiceime-work-wops/outputs/soup-a{025,050,075}/`、評価行とレポートは同作業場所の `runs/soup-a{025,050,075}/` にある。

## 実験2　D-0.8B-drop0の用語誤り

facultyに残っていた条件Dの行別出力を使用した。正解語の表記が整形出力にないval 83件・test-novel 143件を対象とした。同一行でも正解語が異なれば別件と数えた。正解語の同一行内での重複は両splitとも0件。

- 一覧は正解語の厳密な表記で照合した。Qwen仮説はUnicode NFKCで幅を揃え、大小・空白・記号を無視して照合した。英数字列の内部にたまたま一致する略語を除いた。
- Haas 1回目とsegment-mergeは、正解manifestの登録読みを使い、ひらがなとカタカナを揃えて空白・記号を除いた文字列で照合した。英字表記の一致は補足に示す。漢字の同音表記や登録外の読みは読みの件数に含めていない。
- 出力の誤り方は正解文と出力の対応箇所を目視して各語を1分類にした。正規化すると同じ表記は(c)。対応箇所で別の一覧語が語全体または主要部を置き換えた場合は(b)。かな・同音漢字・誤綴りや短縮で元の語の音または表記が残る例は(a)。対応する語句が消えた例は(d)。一覧外の別語や別の意味への書き換え、反復で文が崩れた例は(e)。集計はこの目視判断に依存する。
- 語の種類は排他的に判定した。数字またはハイフン以外の記号を含む語、残りのうち空白・ハイフンを含む複合語、全大文字の英字列、残りの英字1語の順に分類した。英字1語には固有名詞や識別子を含む。

| 観点 | 分類 | val（83件） | test-novel（143件） |
| --- | --- | ---: | ---: |
| 一覧に正解語 | あり | 28 | 56 |
|  | なし | 55 | 87 |
| Qwenに正しい表記 | あり | 10 | 8 |
|  | なし | 73 | 135 |
| Haas 1回目に登録読み | あり | 7 | 30 |
|  | なし | 76 | 113 |
| segment-mergeに登録読み | あり | 3 | 1 |
|  | なし | 80 | 142 |
| 出力の誤り方 | (a) 音写・崩れた表記 | 24 | 75 |
|  | (b) 一覧の別語 | 21 | 27 |
|  | (c) 大小・記号・空白のみ | 2 | 17 |
|  | (d) 脱落 | 15 | 6 |
|  | (e) その他 | 21 | 18 |
| 正解語の種類 | 全大文字の英字略語 | 25 | 2 |
|  | 英単語1語 | 39 | 23 |
|  | 複合語 | 12 | 76 |
|  | 数字・記号を含む語 | 7 | 42 |

登録読みは出ていないがQwenと同じ正規化で正しい表記が出ていたのは、Haas 1回目でval 5件・test-novel 3件、segment-mergeでval 11件・test-novel 33件。たとえば `Sony Semiconductor` はHaas 1回目に登録読み、segment-mergeに英字表記が出ていたが、整形出力は「あの」を反復した。

test-novelの最多は(a)の75件（52.4%）。一覧に正解語がある56件のうち35件も(a)だった。正解語が一覧にありQwenにも正しい表記があった誤りはval 10件・test-novel 6件。正しい手掛かりが入力に残っていても、整形で取りこぼす例があった。表記差だけの17件をすべて正せた場合でも、test-novelは374/500にとどまる。

[誤り例](../../runs/weightops/error-examples.md)に各split・各分類の先頭5件を掲載した。母数が5件未満の分類は全件掲載した。各例に3入力、実際の一覧の抜粋、整形出力、正解を示した。全226件の [目視ラベル](../../runs/weightops/error-labels.tsv) と [集計JSON](../../runs/weightops/baseline-analysis.json) も保存した。

## 実験3　0.8B-drop0と2B-drop0.075の一致

実験2と同じ保存済みrunと、D-2B-drop0.075の既存の行別出力を使用した。両モデルでID、3入力、一覧、promptトークン数が一致した。各正解語の厳密表記が出力に含まれるかを照合した。正解を見て用語単位で選ぶ列は、既存2出力から正しい語を選択できる場合の上限。

| split | 正解語数 | 両方正しい | 0.8Bのみ | 2Bのみ | 片方だけ計 | 両方誤り | 正解を見て用語単位で選ぶ |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| val | 1427 | 1328 | 16 | 33 | 49 | 50 | 1377/1427（96.50%） |
| test-novel | 500 | 313 | 44 | 17 | 61 | 126 | 374/500（74.80%） |

valでは2Bが0.8Bの誤り83件のうち33件を正解した。test-novelでは、0.8Bに2Bだけの正答17件をすべて足しても目標まで26件不足する。合議による改善余地は両splitにあるが、既存の2出力から選ぶだけでは初見語80%に届かない。蒸留や追加生成によって両モデルの共通誤りまで直せるかは未測定。
