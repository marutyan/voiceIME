# ASRの読みのゆれを加えた学習（VAR）

## 目的

用語一覧に正解語があっても、ASRのカタカナが辞書の基本読みから外れると、整形モデルが表記を書かず読みのまま残すことがある。正解語の発音がゆれた入力と、近い読みを持つ別の候補を無視する入力を学習に足す。通常の容量評価で性能を確認し、別に作ったval-ゆれで、変更した語の正答増と未発話語の挿入数をFULL-scratchと比べる。

追加読みの作成法はmainの `docs/experiments/2026-11-24-alt-readings.md`、選択と整形の誤りの区分は `docs/experiments/2026-11-24-error-attribution.md` を参照した。手元の別読みファイルのSHA-256は前者の記録と一致した。実験では一覧生成を固定し、`--glossary-alt-readings` による選択の変更は加えていない。

## 学習データ

facultyの `~/voiceime-work-wops/full1/data/` にある元95,931行と実ASR入力を使用した。元データのうち、omitted語がない、Haas初回・segment-merge後・Qwen 0.6B初回の3入力がそろう行から拡張を作った。用語集は条件Dの学習辞書。held-outの表記と、元の学習データに出たomitted語の表記を両方の拡張の対象から除外し、作成後の評価側照合でtest-novel全500語がheld-out集合に含まれることを確認した。

| 追加データ | 行数 | 元の発話数 | 対象語の種類 |
| --- | ---: | ---: | ---: |
| 正例 | 24,000 | 18,991 | 4,618 |
| 負例 | 9,600 | 9,600 | 1,001 |

学習拡張のseedは173。正例では、正解文に表記が1回あり、入力一覧に入っている正解語を選ぶ。その語の表記か基本読みがASR文にあるときに別読みへ置換する。各入力で置換を別々に抽選し、同じ辞書の別の用語と同音になる候補や、行の別の正解語に重なる位置を避けた。元発話18,991件に1例ずつ作り、そのうち5,009件に異なるASR入力の2例目を加えた。変更した入力は1本が3,548行、2本が9,766行、3本が10,686行。正解文と一覧は保存したまま。

| 正例の変更 | 置換箇所数 |
| --- | ---: |
| 別読みファイル | 15,391 |
| 長音の追加・脱落 | 18,697 |
| 促音の追加・脱落 | 4,609 |
| 仮名の置換 | 4,091 |
| 1文字の脱落 | 15,466 |
| 語尾の変化 | 883 |

負例は正例の40%。正解文にある4文字以上のカタカナ区間で、辞書の表記・読みと一致せず、正解用語に含まれず、ASR入力にも残る区間を普通語として扱った。その区間と基本読みの編集距離が1の候補を163行、距離2を9,437行で加えた。元の発話に表記や読みがある候補は使わなかった。一覧が20語のときは末尾側の発話外候補1語と置き換えた（8,790行）。一覧にあった正解語を外した行は0件だった。ASR入力と正解文は保存したまま。 [件数と例20件](../../runs/weightops/var1/generation-audit.json) · [初見語の分離確認](../../runs/weightops/var1/novel-split-audit.json)

fix1の用語差し替え拡張36,778行をバイト単位で保ち、その末尾にVARを追加した。出力は `~/voiceime-work-wops/var1/data/augmentation-var.jsonl`。学習に使う行数は元と拡張を合わせて166,309行。

全166,309行を学習コードから固定seedで1回ずつ取り出した。omitted語の10,191行で、一覧またはsegment-merge後の文に表記があり正解が読みのままの例は0件。両方に表記がないのに正解に表記がある例も0件。語境界での照合から外れた3行は正解に表記文字列があり、読みが残った行ではなかった。新しい全拡張行について、正解文と用語注記が元の行と同一で、正例ではASR入力だけ、負例では一覧だけが変わったことも確認した。 [取り出し監査](../../runs/weightops/var1/verify-dynamic.json)

## 学習と評価

| 条件 | 初期値 | epoch | 学習率 |
| --- | --- | ---: | ---: |
| VAR-cont | `full1/outputs/FULL-scratch/best` | 1 | 1e-5 |
| VAR-scratch | 元のQwen3.5-0.8B | 2 | 2e-5 |

両条件とも全層、batch 16 × accumulation 2、seed 0、一覧上限20、無作為に混ぜる語は最大8、用語drop 0。元データに実ASR出力が無い行はFULLと同じ合成ASRを使う。970行のval-selectで最良の重みを選び、`var1/outputs/<条件>/{best,final}` に保存する。 [学習と評価の実行引数](../../runs/weightops/var1/train-and-eval.sh)

- 通常の容量評価はfix1の `capacity-eval.sh` を使用し、Haas初回＋Qwen 0.6Bで選んだ上限20・32・48の各一覧でFULLと同じ採点を行う。valの1,427語、test-novelの500語、一覧内外の正誤、未発話語挿入、言い直しタグの削除を集計する。
- val-ゆれはseed 913で、通常のval上限32の一覧を固定して正例の変換を適用した。変換できた447行を使用し、変更語447出現・全正解864出現を分母にする。1本、2本、3本のASR文を変更したのは順に56、163、228行。通常評価の同じ行・同じ語の正答数も集計する。未発話語の挿入はFULLと同じ定義で、一覧またはmanifestの用語集にある語のうち、正解と発話に表記も読みも無い語を数える。 [val-ゆれの監査](../../runs/weightops/var1/val-variants-audit.json)

## 分かったこと

- VAR-scratchはval-ゆれで変更語の正答が432から437に増え、未発話語の挿入は24から18に減った。改善は主に3入力とも変更した行（221→227）に見られた。同じ行の全正解語は831→821で、変更語の改善は他の用語を含む正答数の改善にはつながらなかった。
- VAR-contのval-ゆれの変更語はFULL-scratchと同じ432/447で、未発話語の挿入は21件だった。通常の上限32では言い直しの削除が162→140に減り、val CERは2.67%から2.81%に上がった。VAR-scratchは同上限でval CERが3.09%、言い直しの削除が227件だった。
- VAR-scratchとFULL-scratchは初期値・epoch数が同じだが、VARには拡張による学習stepの増加もある。val-ゆれは合成音声のASR文を文字単位で置換した診断で、置換位置を音声で照合していない。447行中219行は変更した入力が1〜2本で、他の入力には元の認識結果が残る。別seedでの学習と本人の録音での効果は未測定。

```bash
source ~/voiceime-work-wops/rsi1/faculty-env.sh
export CUDA_VISIBLE_DEVICES=""
export PYTHONPATH="$WORK/fix1:$PYTHONPATH"
"$PY" "$WORK/var1/make_variants.py" train
"$PY" "$WORK/var1/make_variants.py" val
```
