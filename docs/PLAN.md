# 開発計画：Mac上で動く日英混在の音声入力モデル

## 目的

MacBook（M3 Pro、メモリ18GB）の手元だけで、話した日本語と英語の技術用語が混ざる発話を、フィラー除去と言い直しの処理を済ませた文章へ変換する。費用をかけず、Aqua Voiceに近い使い心地を目指す。

## 処理の構成

```text
録音（押している間だけ） → 音声認識（ASR） → 整形用の小さなLLM → 入力中のアプリへ貼り付け
                              ↑ 用語集（表記と読み）を両方へ渡す ↑
```

- ASRはWhisper系をMLXで動かす。日英混在の聞き取りが足りなければ、合成音声と公開データで追加学習する。
- 整形用LLMは、大きな教師モデルの出力で1〜2B程度の小さなモデルを学習させる（蒸留）。フィラー除去、言い直しの処理、用語集に沿った英語表記への置き換え、句読点の付与を担う。
- 学習はColab CLIで借りたGPUで行い、推論は手元のMacで行う。

## 目標値（手元のM3 Proで測る）

| 指標 | 目標 |
| --- | --- |
| キーを離してから整形済みの文が出るまでの時間（10秒の発話、中央値） | 1.0秒以下（目安の内訳：ASR 0.4秒、整形 0.4秒、貼り付けなど 0.2秒） |
| 用語の正答率（正解文の用語が、正しい表記で出力に含まれる割合） | 95%以上 |
| フィラーの残存率 | 2%以下 |
| 文字誤り率（CER、正規化後） | 比較の基準（Whisper large-v3＋教師LLM）との差が1ポイント以内。`test-synth`の正解は教師LLMが作るため基準が有利になるので、この判定は`test-user`で行う |

## 評価の決まり

結果を比べる条件は、ここに書いたものに固定する。変更する場合は新しい実験として記録し、変更前後を同じ条件で比べる。

### データと分割

| 集合 | 中身 | 用途 |
| --- | --- | --- |
| `train`、`val` | 教師LLMで作った文章を合成音声で読み上げたもの | 学習と、学習中のモデル選択 |
| `test-synth` | `train`と話者（合成音声の声）を分け、用語の一部（`held-out-terms`）も分けた合成データ | 合成データでの最終比較 |
| `dev-user` | ユーザー本人の録音（約100発話） | モデルや設定の選択に使う。学習には使わない |
| `test-user` | ユーザー本人の録音（約250発話、用語の出現300回以上）。半分は台本の読み上げ、半分は台本なしの自由発話 | 最終評価だけに使う。学習にも調整にも使わない |

- 分割は話者と文章の元（テンプレートと話題）単位で行い、同じ文章が複数の集合へ入らないようにする。
- 用語集の用語の約20%を`held-out-terms`とし、学習データに出さない。推論時に用語集として渡したときに正しく書けるかで、丸暗記でなく汎化しているかを測る。
- 合成音声には自然な言いよどみや早口が無く、合成データだけでモデルを選ぶと選択を誤るおそれがある。そのため本人の録音（`dev-user`）を早い段階で集め、選択に使う。自由発話の正解文は、最良の系で下書きを作りユーザーが直す。
- 乱数のseedは、データ生成で`0`、学習で`0`を既定とする。最終比較では学習のseedを`0, 1, 2`の3つにして、ばらつきを測る。

### 指標の定義

指標の実装は`src/voiceime/eval/`だけに置き、他の場所で同じ計算を書かない。

- **CER**：Unicode NFKC正規化、英字の小文字化、句読点と空白の除去を行った後の、文字単位の編集距離÷正解の文字数。2026-11-22から、同じ語の書き方の違い（「パーセント」と「%」、「とき」と「時」）は誤りに数えない（本人の承認。一覧は`src/voiceime/eval/metrics.py`の`CER_EQUIVALENT_FORMS`）。整形の出力は、数字の直後の「パーセント」を「%」で書く（本人の希望。`src/voiceime/formatter/style.py`）。
- **ASR単体のCER**：正解は`spoken_text`とする。ただし用語をカタカナで書くか英字で書くかの差で値が変わらないよう、正解と出力の両方で、その行の`glossary`の`surface`（大文字小文字を区別しない）を最初の`readings`へ置き換えてからCERを計算する（「読み揃えCER」）。整形後（`stage: e2e`）のCERは`target_text`を正解とし、読み揃えはしない。
- **用語の正答率**：正解文に含まれる用語のうち、出力に正確な表記（大文字小文字を含む）で現れた割合。ASR単体の評価では、カタカナ読みでの一致を「緩い正答率」として別に出す。
- **見えない用語の正答率**：推論時に用語集から除いた語（`--exclude-terms`で指定し、ASRのヒントにも整形LLMの参考にも渡さない語）だけを対象にした用語の正答率。正解文の`terms`に現れる語からseed 0で30%を選んで一覧を作り、評価（`voiceime.eval.report --unseen-terms`）では「見えない用語」と「それ以外」に分けて同じ定義（厳密表記、ASR単体では緩い正答率も併記）で算出する。
- **フィラー残存率**：出力に残ったフィラーの数÷入力の発話に含まれていたフィラーの数。フィラーの一覧は`src/voiceime/eval/`に一か所で定義する。
- **遅延**：キーを離した時点（音声がすべて揃った時点）から整形済みの文が出るまでの時間。ファイルでの評価では、音声を読み込み終えた時点を起点とする。録音中に処理を先に進める方式を使う場合は、その方式を再現して測る。モデルの読み込みと初回実行（warm-up）は除き、5秒、10秒、20秒の発話で中央値と90パーセンタイルを出す。

- **言い直しの正答率**：言い直しを含む発話のうち、訂正後の内容だけが残った割合。フィラー残存率とは別に出す。
- **過剰な編集**：正解文に無い内容の追加、話した内容の削除、話していない用語の挿入の件数。
- **無変更の保持**：フィラーも言い直しも用語も無い発話で、出力が正解と一致した割合。
- **指示への応答**：「〜を教えて」のような発話に、整形せず答えてしまった件数。
- フィラーを含まない発話はフィラー残存率の分母に入れない（分母はフィラーの総数）。連体詞・指示語としての「あの」「その」は、正解文に残っていればフィラーとして数えない。
- 認識器や整形が何も返さなかった発話は、空文字の出力として評価に含める（除外しない）。
- 用語集の大きさを変えて（発話に関係する語だけの場合と、500語を渡す場合）両方で測る。

- **初見語の正答率**（2026-11-22追加）：(a) 学習データに一度も出ないが、推論時の用語集には含まれる語の正答率を目標の判定に使う（基準80%以上）。(b) 学習データにも推論時の用語集にも無い語の正答率は参考値として併記する。

### データの形式

発話は1行1件のJSONL（`data/<集合名>/manifest.jsonl`）で持つ。

```json
{"id": "synth-000001", "split": "train", "audio_path": "audio/synth-000001.wav",
 "spoken_text": "えーと、パイトーチのデータローダーで、いや、データセットクラスで読み込みます",
 "target_text": "PyTorchのDatasetクラスで読み込みます。",
 "terms": ["PyTorch", "Dataset"],
 "glossary": [{"surface": "PyTorch", "readings": ["パイトーチ"]}, {"surface": "Dataset", "readings": ["データセット"]}],
 "speaker": "tts-voice-03", "source": "synthetic-tts", "domain": "ml-research", "fillers": 1,
 "tags": ["self_correction"]}
```

- `spoken_text`は読み上げた文（フィラーと言い直しを含み、英語の用語はカタカナまたは英字）。`target_text`は整形後に期待する文。
- `glossary`の各項目は`surface`（正しい表記）と`readings`（カタカナ読みのリスト）を持つ。用語集ファイル`data/text/glossary.jsonl`も同じ形とする。
- `tags`は発話の種類を表すリストで、`self_correction`（言い直しを含む）、`no_change`（フィラーも言い直しも用語も無い）、`instruction_like`（「〜を教えて」のような依頼の形の発話）、`list`（箇条書きにすべき列挙）、`english_phrase`（英語の句を含む）を使う。
- 音声は16kHz、モノラル、16bitのWAVとする。

推論結果は`runs/<実験名>/<系>.jsonl`へ、`{"id", "system", "stage": "asr" | "e2e", "hyp", "latency_s"}`の形で保存する。

## 作業の流れ

1. 評価基盤と、macOS標準の読み上げ（`say`）で作る小さな動作確認用データを用意する。本人の録音（`dev-user`、`test-user`）を集め始める。
2. 合成データの生成（教師LLMで文章を作り、複数の声の合成音声で読み上げる）をColabで行う。
3. ASRの候補（mlx-whisperのlarge-v3とturbo、kotoba-whisper、macOS標準の`DictationTranscriber`）を手元で比べる。
4. 整形用LLMを蒸留で学習し、MLXの4bitへ変換して手元で速度と精度を測る。学習の入力は、採用候補のASRで合成音声を認識した実際の出力とする（話した通りの文をそのまま入力にすると、ASRが自分でフィラーを落とす、句読点を付ける、用語を誤るといった実際の入力とずれるため）。音声の無い文には、ASRの出力に似せた加工を加えて補う。比較の基準として、読みの曖昧一致による辞書置換とフィラーの正規表現だけの系も測る。
5. 3の結果、ASRの誤りが残る場合は、Whisperを追加学習する。合成音声だけでなく公開の実音声も混ぜ、encoderは固定するかLoRAにとどめる。比較として、ASRに整形済みの文を直接出させる一段の構成も1回試す。
6. 本人の録音で最終評価する。

## 資源の上限

- Colabの使用量は、この段階で合計200 compute unitsまでとする。超えそうな場合は止めて報告する。
- セッションは使い終わったら必ず`colab stop`で止める。
